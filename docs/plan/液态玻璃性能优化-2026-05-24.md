# 液态玻璃导航栏性能优化

日期：2026-05-24
对比基线：REAREye `b8baeb0` 的 `FloatingBottomBar.kt` + `DampedDragAnimation.kt`

## 问题诊断

在 `FloatingGlass + Miuix + UI effects` 全开时，导航栏拖动和页面切换帧率下降。通过对 `SonyRebuildApp.kt` 的 `FloatingLiquidNavigationBar` 与 REAREye 的 `FloatingBottomBar` 逐行对比，定位到以下性能差异：

### 瓶颈 1（架构约束，不可跳过）：三层 backdrop 的 blur 管线

`FloatingLiquidNavigationBar` 包含三层 kyant backdrop 渲染：

| 层 | blur(8dp) | vibrancy | lens | 说明 |
|---|---|---|---|---|
| 外层胶囊 | 常驻 | 常驻 | 24dp 常驻 | 导航栏整体玻璃背景 |
| 重复内容层（alpha=0f） | 常驻 | 常驻 | pressProgress × 24dp | 为选中指示器的 `rememberCombinedBackdrop` 提供 glass tint |
| 选中指示器 | 无 | 无 | pressProgress × 10-14dp | 叠加 lens/高光/阴影/内阴影 |

重复内容层的 blur+vibrancy **不能跳过**：它通过 `tabsBackdrop`（`layerBackdrop`）被选中指示器的 `rememberCombinedBackdrop(backdrop, tabsBackdrop)` 组合使用。空闲时选中指示器虽无 lens/highlight 效果，但其 `onDrawSurface` 仍然叠加表面色并采样 combined backdrop。去掉重复层的 blur 会导致选中指示器从"玻璃质感"退化为"纯色覆盖"——视觉不一致。

尝试过的优化方向及回退原因：
- 空闲时用 `background(containerColor)` 替代 `drawBackdrop` → `tabsBackdrop` 捕获的内容在 idle/press 间切换，选中指示器 `rememberCombinedBackdrop` 出现可见的模糊程度跳变。**已回退。**

结论：重复内容层的 blur 与选中指示器存在架构耦合，不能通过条件跳过优化。优化重心应在拖拽热路径和组合开销上。

### 瓶颈 2（已修复）：onDragStarted 做额外 snapToValue

SonyRebuild 在每次拖拽开始时计算 `touchOffsetFromCenter` 并调用 `snapToValue`（内部走 `mutatorMutex.mutate` 序列化）。REAREye 的 `onDragStarted` 是空 `{}`——因为 `onDrag` 回调中的 `updateValue` 已能正确处理位置跟随。

### 瓶颈 3（已修复）：rememberCombinedBackdrop 在 Modifier lambda 中重建

选中指示器的 `rememberCombinedBackdrop(backdrop, selectedIndicatorBackdrop)` 原本放在 `.then {}` lambda 内，该 lambda 每次 Box 重组都会被求值。虽然 `rememberCombinedBackdrop` 内部有缓存，但在 hot path 上额外创建 lambda 闭包和读 `tabsBackdrop` 状态仍会累积开销。

### 瓶颈 4（已修复）：热路径使用标准 coerceIn/roundToInt

拖拽回调中使用了标准 `coerceIn`/`roundToInt` 而非 Compose 提供的 `fastCoerceIn`/`fastRoundToInt`。后者在编译时更激进地内联，减少函数调用层级。

## 修复方案

### 修复 1：onDragStarted 简化为空

将 `onDragStarted` lambda 从计算触点偏移+snapToValue 改为空 `{}`，与 REAREye 对齐。`onDrag` 中的 `updateValue` 已经以 `targetValue` 为基准（而非当前 `value`），不需要 drag start 时的预偏置。

### 修复 2：rememberCombinedBackdrop 提升到 Box 外部

将 `rememberCombinedBackdrop` 提前到 Box composable 之前赋值给 `combinedForSelected`，避免在 `.then {}` 闭包中每次重组重新创建 lambda。同时 `if` 条件从 `(backdrop != null && selectedIndicatorBackdrop != null)` 简化为 `(combinedForSelected != null)`。

### 修复 3：fast* 数学变体替换

- `coerceIn` → `fastCoerceIn`（panelOffsetPx、onDragStopped、onDrag、velocity layerBlock）
- `roundToInt` → `fastRoundToInt`（onDragStopped 中的 targetIndex）
- 同步更新 `LiquidNavigationDrag.kt` 中 `updateValue`、`snapToValue`、`animateToValue` 的 `coerceIn` 调用

## 未实施的优化及原因

| 方案 | 为什么不实施 |
|---|---|
| 重复内容层空闲时跳过 `drawBackdrop` | `tabsBackdrop` 捕获内容在 idle/press 间切换，选中指示器模糊程度不一致（用户确认回退） |
| 减少重复层 blur radius | 与选中指示器 combined backdrop 共享同一 blur 管线，减小 radius 会改变指示器玻璃质感 |
| 外层胶囊 lens radius 随进度缩放 | REAREye 也常驻 24dp，改为动态会导致整体液态感丢失 |
